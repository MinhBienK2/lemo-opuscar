# Retro — the layout of the library (2026-10-30)

The session this record is about reorganised how the repository holds its content. Before it, every film — a
one-shot or an episode — was a direct child of `films/`, and a channel was a **naming convention** plus a
`CHANNEL.md` that happened to live inside episode 1. After it, a channel is a module of its own, an episode is a
folder inside it, the shared code exists once, and one module knows where the films are.

The work was done as a programme (the six deepening candidates of an architecture review): the channel module,
the discovery module, the scaffold, the generated index, the cast module with its 2D and 3D adapters, and a
channel that carries the library's shape.

## Context

- Before: `films/host-toon-test/`, `films/tram-nghi-nhieu/`, `films/tram-nghi-nhieu-tap-02/`,
  `films/tram-nghi-nhieu-tap-03/`. After: `films/host-toon-test/` (a one-shot) and
  `channels/tram-nghi-nhieu/{tap-01,tap-02,tap-03}/`, plus the new channel `channels/nhan-vat/`.
- The three episodes were **byte-identical copies** of the channel's toolkit: `src/cel.js` (126 lines),
  `src/character.js` (477), `src/broll.js`, `src/sets.js`, `mix.py` (247), `STYLE.md`, the three voice scripts
  and the eight font files — ≈ 840 KB per episode.
- The contract every tool is built against is now [`docs/layout.md`](../../docs/layout.md); the domain words are
  in [`GLOSSARY.md`](../../GLOSSARY.md).
- The gate after the change: `sh core/render/review.sh channels/tram-nghi-nhieu/tap-0{1,2,3}` → **PASS** on all
  three (filmcheck, drawcheck, claims, facts, readcheck, voice, stills, contact sheet, loudness, black frames).

## What went well

- **The shared code was copied out before anything moved.** The channel's `rig/`, `mix.py`, `fonts/` and
  `voice/` were created from the newest copies (tap-03's `sets.js`, which carries the `{ lamp: false }` fix that
  tap-01 never received) before the episodes moved, so no episode lost a file it still needed.
- **The move was verified by the repository's own gate**, not by a diff: all three episodes pass the full review
  loop at their new depth, with the voice transcribing back line by line ("every line transcribes back", 0
  mismatches) through the channel's `asr_vi.py`.
- **The new module was written against the old habit, not around it.** `core/render/films.mjs` classifies a folder
  by what it holds (a channel holds `CHANNEL.md`, a film holds `build.sh`), so the layout can move again without
  touching a single caller.
- **The cast module has two adapters, not one.** The same character is drawn on a 2D canvas and built in
  three.js from one spec, and the sheet that shows both was rendered and looked at.

## Findings

### L1 — medium — The guides told an agent that a film lives in `films/<name>/`, and the one pointer to a
### channel's map named a folder that does not exist

**Evidence.** `AGENTS.md` pointed at `films/<channel>/CHANNEL.md` — a path that never existed; the map lived in
`films/tram-nghi-nhieu/CHANNEL.md`, i.e. inside episode 1. `films/README.md`, the index an agent reads first,
never mentioned `CHANNEL.md` at all. The retro of 2026-10-30-tap-03 (P9) recorded the cost: the session found
the channel's process by accident, as the eleventh file it listed, and hunted for the whisper model anyway.

**Impact.** A session that starts an episode of a known channel rediscovers the channel — the same way, every
time.

**Guard now.** `AGENTS.md` ("Where things go", and the row for the next episode of a channel) · `TECHNIQUE.md`
§13 names the reference channel · the contract in [`docs/layout.md`](../../docs/layout.md) · the channel's own
`CHANNEL.md` says what the channel holds and what an episode holds.

### L2 — critical — One implementation in three places

**Evidence.** `cel.js`, `character.js`, `broll.js`, `mix.py`, `STYLE.md`, the three voice scripts and the eight
font files were identical in all three episodes; `src/sets.js` was identical in tap-02 and tap-03 but **not** in
tap-01 — the `{ lamp: false }` fix (the desk lamp over the page the character writes on, T8) was made in tap-02
and copied forward, so **tap-01 still carries the defect**. The channel's own `CHANNEL.md` prescribed the cause:
*"nhân bản thư mục này cho tập mới"* — copy this folder for the next episode.

**Impact.** A fix to the rig reaches the newest copy and stops. The channel had three implementations of one
character rig and no single place to fix.

**Guard now.** The shared code exists once, in the channel; the episode reaches it by a relative path
(`../../rig/cel.js`) and its `build.sh` calls the channel's `mix.py` with `FILM=` the episode ·
`core/render/new_episode.sh` attaches the shared code instead of copying it · `CODING_STANDARDS.md` R7 makes a
copy inside an episode a defect.

### L3 — high — Every tool that walked `films/` found the one-shots and missed the episodes

**Evidence.** Six tools enumerated films one level deep: `.github/workflows/films.yml` (five loops),
`tools/install_precommit.sh` (three `sed` extractions), `tools/release.py` (`os.listdir`),
`tools/supervise.sh`, `tools/check_films_index.py` and `core/render/filmcheck.mjs`. Under a nested layout **none
of them fails loudly**: `films/<channel>/` has no `src/`, so every loop `continue`s, and
`core/render/drawcheck.mjs` printed *"no src/ …; nothing to check"* and **exited 0**. The pre-commit hook's `sed`
captured the *channel* segment instead of the episode and ran the checks against a folder with no source.

**Impact.** The gate would have gone green while checking nothing — "a gate that cannot fail the build is
decoration", in a new shape.

**Guard now.** `core/render/films.mjs` — the one module that knows where the films are (the marker decides, never
the depth); the CI steps, the pre-commit hook, `tools/release.py` and `tools/supervise.sh` ask it for the list ·
`core/render/drawcheck.mjs` says what it could not check and exits non-zero.

### L4 — medium — The index was written by hand, and one of its rows promised a runtime the mix did not deliver

**Evidence.** `films/README.md` was a markdown table parsed by a regex; its row for episode 3 claimed `20:00`
while the mix measured **19:55** (P12), and an earlier row named a movie that did not exist (`triu` for `trieu`,
P6). Both were found by a check that reads the table; neither could be prevented by writing carefully.

**Impact.** The index is a second truth, and it drifts the moment a film's length changes.

**Guard now.** `tools/gen_films_index.py` writes `FILMS.md` from each film's own manifest (`film.json`) ·
`tools/check_films_index.py` compares every manifest with the file on disk and the index with the manifests; a
film whose movie does not exist yet is reported *in preparation* and does not fail the check.

### L5 — medium — A film that could not be checked read as a pass

**Evidence.** `core/render/drawcheck.mjs` exited 0 for a folder with no `src/` (P14 recorded the same shape in the
first session); the CI steps `continue`d when they found no film; `tools/install_precommit.sh` ran the checks
against a folder that does not hold the film.

**Impact.** Silence and success look the same in a log.

**Guard now.** `core/render/drawcheck.mjs` says what it could not check and exits non-zero · every CI step fails
when the discovery module finds no film · the pre-commit hook maps a staged path to the film that owns it.

### L6 — high — A guard that silently stopped guarding: the `rect` rule no longer applied to the episodes

**Evidence.** `core/render/drawcheck.mjs` derives the calling convention of `rect()` from the film's **own**
`src/*.js`. After the move, the helper lives in the channel's rig (`rig/cel.js`) and the episode imports it as
`../../rig/cel.js`, so the scan found no helper and printed *"no rect helper …; the rect rule does not apply"*
while the step still said **ok**. The rule that caught the `rect()` codemod damage in the first session was no
longer running for three of the four films.

**Impact.** The strongest drawing guard in the library — the one that caught 8-argument and inverted-corner
calls — was off, and the log said everything was fine.

**Guard now.** `core/render/drawcheck.mjs` follows the episode's relative imports, so the helper is found in the
channel's rig, and a drawing audit that found no helper says so and does not read as a pass. A rule that is only
*found* but not *applied* is not restored: the check is run against a deliberately broken copy of an episode. The
same blind spot existed in CI, which parsed only the films' own `src/` — the channel's rig and the cast module
were never parsed at all, and the parse step copied every file under its **basename**, so the `film.js` of four
films and every style demo overwrote itself and only one of them was ever checked. The parse step now covers
`channels/`, `films/`, `core/cast/` and the styles, copies each file under its whole path, prints how many files
it parsed, and fails when it parsed none. Proven: a deliberate syntax error in the rig makes the step fail with
`::error::channels/tram-nghi-nhieu/rig/cel.js does not parse`.

### L7 — high — The gate died on the voice step instead of skipping it

**Evidence.** `core/render/review.sh` looked for the ASR script **inside the episode**; after the move it lives in
the channel. The review fell back to `core/tts/asr_check.py` (English, `base.en`), the model's cache on this
machine is a symlink to an unmounted drive, the checker exited 2, and `set -e` killed the whole review right
after it printed `--- voice`. The branch that was written to print *"skipped: no whisper model available"* (T7)
could never be reached.

**Impact.** A missing model was a failed gate, and the failure looked like a broken film.

**Guard now.** `core/render/review.sh` finds the ASR script in the episode **or** in the channel, runs it with
`--model small`, and captures its status instead of letting `set -e` kill the gate: a model error skips, a
mismatch fails, any other non-zero fails.

### L8 — medium — A 3D page renders blank and the render still passes

**Evidence.** On this machine (Linux, no GPU drivers) the headless browser's default backend gives the page a
WebGL context whose **shaders do not validate**: the cast sheet's 3D half came out white, the page logged
`THREE.WebGLProgram: Shader Error … VALIDATE_STATUS false` and `no valid shader program in use`, and
`still.mjs` reported success. `core/render/browser.mjs` warned only about *software* rendering, never about a
context that exists but cannot draw.

**Impact.** A 3D film would be published with a blank panel, and every check would be green.

**Guard now.** `core/render/page.mjs` recognises the page's own WebGL failures in the log (`VALIDATE_STATUS`,
`no valid shader program`, `Shader Error`, `CONTEXT_LOST_WEBGL`) and prints the actionable note —
`LEMO_ANGLE=swiftshader` on Linux, `metal` on macOS · `core/render/browser.mjs` probes the context itself (lost,
or a program that does not link or validate — both shader stages, because a vertex-only program is an
INVALID_OPERATION, not a verdict). Proven with the two cases: the default backend prints the failure note, the
`swiftshader` backend does not, and a 2D film prints neither.

**The first version of this guard cried wolf** and was corrected in the same session: it read
`isContextLost()` after the probe had already called `loseContext()`, and its test program had no fragment
stage. A guard that fires on a healthy render is switched off — it is the lesson this repository has recorded
twice already ("a check that cries wolf gets switched off").

### L9 — medium — The supervisor never found the film under production

**Evidence.** `tools/supervise.sh` selected the film with `find -newermt '-2 days'` — a date GNU `find` does not
understand — so the loop never matched and the supervisor exited with "no film under production". It also looked
only in `films/*/`.

**Impact.** The witness that ran every fifteen minutes watched nothing, for as long as the bug was there.

**Guard now.** `tools/supervise.sh` asks the discovery module for the films and computes the date with
`date -d`; it now selects `channels/tram-nghi-nhieu/tap-03`.

### L10 — medium — The rule that keeps a treatment in the repository matched one level

**Evidence.** `.gitignore` ended with `!films/*/TREATMENT.md` (the fix for F10 in the first retro). An episode
one level deeper — exactly what this change made — is **not** re-included by that rule, and the blanket
`**/TREATMENT.md` keeps it ignored: the treatment would have stayed on disk and never reached the repository,
with no error anywhere.

**Impact.** The regression F10 recorded, one level deeper.

**Guard now.** `.gitignore` carries `!channels/*/*/TREATMENT.md` as well · `tools/check_tracked.py` asks git
whether each film's treatment can be committed (`git add --dry-run`) and fails when it cannot — proven by
commenting the rule out and watching the check fail on all three episodes.

### L11 — low — The plugin edition would have shipped pointers to files it does not ship

**Evidence.** The directory edition (`tools/directory.py`) ships the guides and the styles and deliberately leaves
out the films. After the change the shipped `AGENTS.md` pointed at `channels/<channel>/CHANNEL.md` and the shipped
`TECHNIQUE.md` named two channels that the edition does not contain — both dangling.

**Impact.** The plugin edition would have told the agent to read a file that is not there.

**Guard now.** `tools/directory.py` (EDITS) removes the channel rows and the channel section for that edition and
says that a film there is a one-shot · the edition's build stops by itself when a replacement no longer matches,
which is how this was caught.

### L12 — medium — The voice step failed on a film whose speech had never been generated here

**Evidence.** `films/host-toon-test` has no `.wav` at all: the speech is generated on the machine and
`**/*.wav` is gitignored, so it is not in the repository. The voice step copied what it found into its scratch
folder and ran the checker on a file that was never there: `soundfile.LibsndfileError: Error opening
'…/voice/hook1.wav'`, and the step **failed** — a failure that says nothing about the film.

**Impact.** On any fresh clone the one-shot's gate fails on a local artefact, and the real finding (the readcheck
one) is buried under a crash.

**Guard now.** `core/render/review.sh` counts the film's own `.wav` files first: with none, the step prints
*"skipped: this film has no generated voice (the speech is local; build it to check the narration)"* and the gate
carries on — the same treatment a missing whisper model already had. The three episodes keep their speech on the
machine and still run the step: *"ok: every line transcribes back"*.

## Open items

- **The directory edition does not ship `channels/`** — by design: the channels are the user's own work, and the
  committed movies (185 MB for episode 3) have no business in a plugin. The edition therefore has no scaffold to
  run and no channel to start an episode in; its guides say so, and the pointers to files the edition does not
  ship (`docs/layout.md`, the channel rows) are rewritten by `tools/directory.py` (EDITS).
- **`tools/release.py check --strict` still fails** on this machine: 66 × "no film `styles/<slug>/<slug>.mp4`
  here" (the styles' demo films are release assets, absent locally), "too big (194.9 MB)" for episode 3's movie
  (over the 60 MB limit) and one "local path" in `improvements/README.md`. All three predate this change and are
  the maintainer's release step, not a film defect.
- **`films/host-toon-test` fails the review** on one step, and it is older than this change: a readcheck
  finding ("BAD map:5 tháng … overlaps the subtitle band" — a caption drawn under the subtitles, a film defect;
  the original `review.sh` from HEAD fails on the same finding). The voice step now skips itself on that film
  (L12), so the caption is the only thing left to fix: the card and the subtitle band must not share the bottom
  of the frame.
- **`proportions.body` in a cast spec** is "the height of the body under the head, in head units" — the reading
  the cast module documents. A torso length would be a different character; the spec says which one it is.
- **The change was committed by the user, not by an agent.** The working tree held the user's uncommitted work, so
  no agent staged or committed anything (`CODING_STANDARDS.md` R3); the moves were plain `mv`, and git read them
  as renames. The user committed the result themselves (`0264ada`, `71df50e`, `a73802c`).
