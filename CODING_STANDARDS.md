# Coding standards

The judgement rules of this repository: the things a check cannot enforce, so a reviewer has to read them.

## How to use

Read this **at review time**, not at implementation time: when you are asked to look at someone else's change, these rules are the ones to judge it by, together with the file's own conventions. Each rule exists because a session in this repository broke it — the evidence is in [`improvements/retro/`](improvements/retro/).

## The rules

**R1 — Edit files with the file-editing tools (`edit`, `ast_edit`, `write`), never with a shell heredoc or a shell redirect.** A shell write can truncate a file before it fails, and it leaves no record of what was intended. When the snippet is too long for an exact-match edit, use `python3 tools/replace.py <file> <old-snippet> <new-snippet>`: it counts the matches, refuses to write unless there is exactly one, and renames a whole new file over the target — so the target is never half-written. When the edits are many and long, give them to the same tool in one command: `python3 tools/replace.py --batch - <<'JSON'` with a list of `{"file": ..., "old": ..., "new": ...}` on stdin — every edit is counted, every file is checked before any file is written, and nothing is left on disk. A long snippet may also live in a file (`{"old_file": ..., "new_file": ...}`), so nobody has to hand-write JSON full of quotes and newlines: the usual workaround for that is a script that rewrites the JSON first, which is the thing R1 forbids. A session that writes its own python script to do this work has written the thing R1 forbids, and it leaves no record of what it changed.

**R2 — A codemod is not applied until you have re-read the file it touched.** A patch script that aborts part-way leaves the file half-patched, and the edits it did not land are invisible; report which ones did not land instead of assuming.

**R3 — Never commit a file the user has modified.** Snapshot their version, stage only your own change, and never `git add -A` over a dirty working tree; check `git diff` (staged vs unstaged) before committing.

**R4 — Do not write "verified" in a report unless the output of the check is in hand.** A report that claims a check that never ran is worse than no report.

**R5 — Long jobs: start them in the background and continue with other work; never poll with `sleep`.** The harness delivers the job output on its own; polling burns wall-clock time and, while the shell is busy, later commands lose their variables.

**R6 — A number on screen wears the source's wording, not the film's.** The source says "94 independent tests"; the film that says "94 nghiên cứu" has changed the claim, whether or not the number is right. When the film's research file words a number differently from the paper, use the file's wording. A check can report the pair (`tools/check_claims.py`); the judgement that a shortening is fair is yours.

**R7 — A channel's shared code lives in the channel, and an episode is its own film.** The shared implementation exists once: a copy of the rig, the mix, the fonts or the voice scripts inside an episode is a defect, not a convenience — it is a second version that drifts, and the episode that reaches the channel by a relative path and the one that carries a copy no longer draw the same picture. A change to the shared code is made in the channel, once, and every episode is rebuilt against it; never in one episode. And an episode names its own movie: that name is the film's identity in the library — the file the build writes, the transcript beside it, the row the index prints — and it belongs to no other film, one-shots and episodes alike. An episode that keeps the previous episode's name ships under that name; two films that write the same movie overwrite each other.

**R8 — The `asr` key in `voice/lines.json` is reserved for number spellings and foreign loan words.** Whisper writes numbers as digits ("2000" vs "hai nghìn") and foreign proper names in their original Latin spelling ("Tokyo" vs "Tô-ky-ô"); `asr` provides that expected alternate form. Never use `asr` to mask mispronounced or slurred Vietnamese words ("vạch trần" → "vặt trưng", "rà soát" → "trà xoát"). If TTS mispronounces a word, fix the audio generation or adjust pronunciation phonetically in `say`.

**R9 — Wait for the agent, never for the file.** A subagent reports when it is done; that report arrives on its own. Asking the filesystem instead — `ls -l` on the file it is writing, `stat`, a `sleep` and look again — is a poll loop: it burns the turn, it never ends, and it decides nothing. The same command five times in a row is a poll, whatever it looks for. Two agents must never write the same file: while a subagent owns a file, the parent reads it and waits. The same shape in another costume is starting a long job with `nohup … > log 2>&1 &` and then reading the log: the harness was never told the job exists, so nobody reports when it ends, and the session polls. Run long jobs with the harness's own background mechanism (`Bash` with `run_in_background`) — it reports the exit on its own, and the output is read once, at the end. And do not redirect that job's output to a file of your own (`> round.log`): the harness already carries the output, so the file is a thing that does not change — reading it again is reading a thing that does not change. One episode read its own nine log files 111 times this way while its report said "R9: 0": thirty-four of those reads were one props round's log, over seventy minutes, each read followed by `date` and `ps -o etime=` to see whether the round was still alive. The rule is now enforced as well as stated: a `PreToolUse` hook in `.claude/settings.json` (`tools/hook_bg_log.py`) counts the reads of each log file in the session and **blocks the third read** of the same file, with the right way to do it in the message.

**R10 — Use the library's tool for the job it already does.** The library has one tool per recurring job: `core/render/still.mjs` renders frames, `core/render/sheet.py` tiles them into one contact sheet, `core/render/review.sh` measures a built movie, `tools/frames_at.py` cuts one frame per narration line out of a built movie, `tools/replace.py` makes a scripted edit safely. A hand-rolled `ffmpeg` montage is the same tool written again, worse: it names no frame, it breaks when a frame is missing, and the next reader has to work out what it was doing.

**R11 — Read a range, not the whole file, and never the same big file twice for one edit.** A file of two hundred kilobytes read to find one function buys nothing: grep for the name, then read the lines around it (`offset`, `limit`). Reading the same file again after an edit is the expensive habit of a long session — the edit tool already knows the file's current state. The same file read fifteen times over is a session paying for the same context again and again; the cure is a map of the code (what lives where, with line numbers), written once and kept beside the source. The supervisor counts the reads per file and reports the ones that repeat — and a `PreToolUse` hook in `.claude/settings.json` (`tools/hook_stale_read.py`) blocks the third read of a **large file that has not changed since the last read** (the file's mtime is the test, so reading a file right after editing it is still allowed), with the range-reading alternative in the message. It also blocks the **tenth whole-file read of the same path in one session**, changed or not: the file most re-read is the one just edited, and a read of a file you have just written brings nothing — its content is already in your context.

**R12 — Look at the sheet, not at one frame again and again.** An image costs about a megabyte of context; a text file costs a few kilobytes. A session that opens the same frame seventeen times is paying for the same picture seventeen times, and the sheet of twelve frames would have shown it once. When a picture needs checking, open the sheet the tool already made (`sheet_*.jpg`, `core/render/sheet.py`), open the frame only when the sheet cannot answer the question — and remember that a cell small enough to hold sixty frames is a **map**, not evidence: it loses the contrast and the size that carry the claim, so a line can look broken in a sheet and be fine in the film (and the other way round). cut the line out of the movie itself (`tools/frames_at.py --lines c32`) before calling it broken — and the same rule binds whoever is watching: a verdict sent to another session about a weak line is a verdict that costs someone else a re-render, so it waits for the frame at full size, and write down which frames have been looked at so the next round does not look again. The supervisor counts the image reads per file and reports the ones that repeat.

**R13 — A script another session is running must not be edited under it.** A shell reads a script as it executes it, so any edit that changes the file's bytes shifts what the running shell reads next: it resumes at an offset that no longer means the same thing, and the run dies in a way that looks like the film's fault. This happened once while a supervisor was editing the channel's `review.sh` in the middle of a review round: the round was about to fail on a byte offset, not on the picture. When a change is needed while a review or a build is running, write the new file beside the old one and swap it in when the run ends — and say so, so the session that was running it knows what happened.

## The boundary

**Mechanical rules live in checks, CI jobs and hooks — not here.** Arity, syntax, citations, the film's own identity, the numbers on screen, the index and the review loop are enforced by `core/render/drawcheck.mjs`, `core/render/filmcheck.mjs`, `sh core/render/review.sh <folder>`, `tools/check_citations.py`, `tools/check_claims.py`, `tools/check_films_index.py`, `tools/release.py check --strict`, `.github/workflows/films.yml` and `tools/install_precommit.sh`. The layout itself is enforced the same way: `core/render/films.mjs` is the one module that knows where the films are, so every tool and every CI step finds them by asking it; `core/render/new_episode.sh` writes an episode that starts empty of the previous episode's identity; `core/render/filmcheck.mjs` reports an identity file that is byte-identical to another film's and a build name that belongs to another film; `tools/gen_films_index.py` writes `FILMS.md` from the manifests and `tools/check_films_index.py` compares every manifest with the file on disk and the index with the manifests.

What no tool can decide is in R7: whether a copy of the channel's shared code inside an episode is a convenience or a defect, and where a change to that shared code belongs. This file holds only what those tools cannot decide.

If a rule can be a check, write the check and leave here at most the sentence saying why the judgement is still needed.

**R14 — A wait loop must not be able to match itself.** `until ! pgrep -f "episodes/tap-01/build.sh"; do sleep 15; done` — the shell that runs the loop carries that string in its own command line, so `pgrep -f` finds the loop itself, the condition never becomes true, and the wait outlives the job it was waiting for. The same shape in `pkill -f` kills the shell that runs it. Write the pattern so it cannot match itself (`pgrep -f "[t]ap-01/…/build.sh"`), or check a pid written to a lock file; and kill a job by pid, never by pattern.

**R15 — A headless agent must be able to run the commands it needs.** When a script spawns an agent that is not a person — `claude -p`, a reviewer in a round, a job in a cron — every permission prompt has **no answerer**: the call comes back "This command requires approval", and the agent tries again and again until a wall clock kills it. The run looks busy (its first log line is printed) and produces nothing. Give the headless agent the permissions its work needs — `--dangerously-skip-permissions` when it works in a folder of its own outside the repository — and watch its output while it runs: if the log says a command needs approval, stop it and say so in seconds, not in hours. This happened in the props round of one episode: 37 minutes to crop one image, then the round died with no report.
